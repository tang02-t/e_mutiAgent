## 2. 智能体、工具与核心模块

### 2.1 五个智能体

| 名称 | 文件 | 职责 | 常见代称 |
|---|---|---|---|
| Planner | `src/agents/planner.py` | 决定下一步动作：`ask`（追问用户）/ `call_tool`（调工具）/ `conclude`（给结论） | 规划器；「被评 Planner」指被替换为微调模型的它 |
| Retriever | `src/agents/retriever.py` | 执行 Planner 的工具计划，收集证据 | 检索器 |
| Generator | `src/agents/generator.py` | 依据证据写诊断结论；v2 可输出结构化 claims | 生成器 |
| Validator | `src/agents/validator.py` | 审核结论；v1 整体打分，v2 逐条核查声明并路由 | 验证器 |
| Reflector | `src/agents/reflection.py` | 对检索块打 0–3 分过滤低相关证据 | 反思器、反思 |

### 2.2 五个工具（`src/tools/tool_registry.py` 的 `TOOL_SPECS` 注册表）

| 工具名 | 实现 | 功能 |
|---|---|---|
| `fault_attribution` | `src/tools/fault_attribution.py` | DGA 故障归因：贝叶斯网络 + 三比值法混合，输出 8 类故障概率与 `uncertainty` 块 |
| `rag_search` | `src/tools/local_kb.py`（`LocalKBRetriever`）| 离线文献检索：BM25 子块 + 锚点两路 RRF |

### 2.3 归因引擎相关

| 术语 | 含义 |
|---|---|
| DGA | Dissolved Gas Analysis，油中溶解气体分析。五种特征气体 H2 / CH4 / C2H6 / C2H4 / C2H2，有时加 CO / CO2 |
| 三比值法 | DL/T 722 规定的 C2H2/C2H4、CH4/H2、C2H4/C2H6 三个比值编码判故障 |
| DL/T 722 | 《变压器油中溶解气体分析和判断导则》（DL/T 722-2014），中国电力行业标准，提供注意值 |
| IEC 60599 | 国际电工委员会 DGA 解释标准；R1 数据的标签 NF / PD / D1 / D2 / T1 / T2 / T3 即其编码（正常 / 局放 / 低能放电 / 高能放电 / 低温 / 中温 / 高温过热） |
| CPT | Conditional Probability Table，贝叶斯网络的条件概率表 P(征兆 \| 故障)。中期为人工近似，v2 从 R4 极大似然学得 |
| expert / calibrated | 两套归因引擎参数。`expert` 为人工规则参数；`calibrated` 为 R5 学习并 5 折校准的参数。由 `configure_engine()` 切换 |
| ECE | Expected Calibration Error，期望校准误差；置信度与实际准确率的差距，越小越好。校准前 0.101 → 后 0.055 |
| w_f | 按故障类别 f 的规则 / 概率融合权重（校准时可学习） |
| 温度（temperature） | 校准用的 softmax 温度参数，不是物理温度 |
| 负观测 / 「未检测」 | 用户明确说某气体未升高时作为证据输入（v1 只支持「升高」） |
| 8 类故障（`FAULT_IDS`） | `winding_deformation` 绕组变形 / `winding_short_circuit` 绕组匝间短路 / `core_grounding` 铁芯多点接地 / `bushing_fault` 套管故障 / `olc_fault` 分接开关故障 / `partial_discharge` 局部放电 / `overload_overheating` 过载过热 / `insulation_degradation` 绝缘老化；另有 `normal` 正常 |
| 14 类征兆（`SYMPTOM_IDS`） | 7 种气体升高 + 油温 / 绕组温度 / 负载 / 振动升高 + 局放告警 + 产气速率过快 + 总烃（TDCG）升高 |
| TDCG | Total Dissolved Combustible Gas，总可燃气体（总烃） |

### 2.4 主线一术语

| 术语 | 含义 |
|---|---|
| EIG | Expected Information Gain，期望信息增益。对每个未观测征兆计算「问了它后故障分布熵期望下降多少」，选最大者追问。实现 `src/tools/eig.py` |
| VoI | Value of Information，信息价值 = EIG − λ × 获取成本；`eig_cost` 策略用它 |
| 熵 / 熵阈值 | 故障概率分布的香农熵；低于阈值（默认 0.8）则 Planner `conclude` |
| `eig_decide` | LLM 不可用时的确定性回退决策函数 |
| planner_strategy | Planner 策略开关：`free`（自由规划，LLM 自选）/ `active`（主动策略，依 EIG 推荐追问） |
| B-5 四种问询策略 | `random` 随机问 / `fixed` 按 IEC 60599 固定顺序问 / `eig_greedy` 只按 EIG（λ=0）/ `eig_cost` EIG 减成本（本文方法） |
| 部分观测 | 只看到部分气体读数的诊断情形，由 D12 模拟；light / medium / heavy 对应遮蔽 1 / 2 / 3 种气体 |
| `pending_questions` | Planner 中断时留在状态里的待追问列表 |
| inquiry 节点 / 追问轮 | 工作流里处理 `ask` 动作的节点；`max_inquiry_rounds` 限制最多追问几轮 |

### 2.5 主线二术语

| 术语 | 含义 |
|---|---|
| claim / claims / 声明 | Generator 输出的原子结论句，每条带 `type` 与 `evidence[]`（指向工具结果或文献块）。定义在 `src/agents/claims.py` |
| ClaimChecker / 声明核查器 / 约束核查器 | `src/agents/claim_checker.py`，逐条核对声明是否有证据、数字是否一致、是否越界 |
| 四类约束 | `DATA` 数字与工具结果一致；`EVIDENCE` 引用的证据真实存在；`APPLICABILITY` 结论适用于该设备 / 数据集 / 窗口；`SAFETY` 安全前提未被删、无「无需处理」类矛盾 |
| 声明判定 | 每条 `pass` / 不通过；`unsupported_ratio` = 不通过声明占比 |
| Validator 三路路由（`validator_mode=route`） | `pass` 结束；`revise` 回 Generator 修订；`supplement` 补证：回 Retriever 再调工具后重生成；均不行则 `abstain` 弃答 |
| 补证 / 补证重规划 | 即 `supplement` 路径，C-3 实现 |
| 弃答（ABSTAIN） | 证据不足时拒绝给结论 |
| 故障注入 | D11 的构造方式：在干净草案里人为植入一处错误，看核查器能否抓到 |
| 四类注入 × 15 子类 | `numeric_tamper`（改概率 / 气体浓度 / 异常数 / 预测温度）、`fake_reference`（不存在的块 / 图谱边 / 调用、伪造原文、把知识库当检测）、`applicability_swap`（换数据集 / 换设备 / 换预测窗口）、`safety_premise_removed`（删 DGA 前提、「无需处理」矛盾） |
| E1 / E2（验证器评测场景） | E1 仅注入错误；E2 注入 + 缺证（同时删掉支撑证据）。注意与 PLAN 的 E-1 / E-2 阶段无关 |
| 错误通过率 | 含错误的草案被 Validator 放行的比例（v1 100% → v2 3%） |
| 无依据结论率 | 最终答案里没有证据支撑的声明占比 |
| v1 Validator / 整体评分 | 旧验证器（`claim_check=off`）：对整段答案打一个分，不逐句核对。validator_eval.md 中三组分别记为 `v1` / `v2_check` / `v2_route` |

### 2.6 主线三术语

| 术语 | 含义 |
|---|---|
| SFT | Supervised Fine-Tuning，监督微调；在金标 Planner 轨迹上训练 |
| DPO | Direct Preference Optimization，直接偏好优化；用 (chosen, rejected) 对训练，无需奖励模型 |
| GRPO | Group Relative Policy Optimization，一种在线 RL 方法；决策 D-2 决定不用 |
| LoRA | Low-Rank Adaptation，低秩适配微调；百炼 `efficient_sft` 与 `dpo_lora` 都是 LoRA |
| 百炼 | 阿里云百炼模型平台，负责训练与部署；脚本在 `training/planner_bailian/` |
| 魔搭 / ms-swift | ModelScope 平台及其训练框架；v1 备选路线，脚本在 `training/planner_sft/` |
| `qwen3-8b` / `qwen3.7-flash` | 前者为被训练的 Planner 基座（百炼支持 SFT + DPO）；后者为跑基线、口语化改写与评测裁判的云端模型 |
| Qwen3-VL-8B | v1 曾计划的多模态基座，已弃用 |
| ChatML / `tool_calls` 风格 | 百炼训练文件的对话格式；`tool_calls` 为 OpenAI 风格函数调用字段 |
| LLaMA-Factory 格式（lf_train.json） | 另一种导出格式，供魔搭路线使用 |
| chosen / rejected | DPO 偏好对中的优选与劣选回答 |
| 候选 | 同一 prompt 下采样得到的多条 Planner 回答，用于打分配对 |
| 六维打分 | `format` 格式合法 / `tool` 工具选择 / `schema` 参数结构 / `business` 业务结果有效 / `faith` 声明忠实度 / `ask` 追问一致；再减成本 |
| `score_exec` / `score_full` | 只用前四项（执行信号）的打分 vs 六项 + 成本（加入验证信号）的打分 |
| 执行信号 / 验证信号 | 执行信号 = 工具调没调对、结果有没有；验证信号 = 结论有没有证据、该问有没有问。主线三论点：后者更有用 |
| 金标扰动 | 对金标 Planner 回答做 6 类人工破坏（`no_ask` / `bad_schema` / `spurious_call` / `extra_calls` / `wrong_tool` / `bad_format`）以验证打分函数方向正确 |
| 口语化改写 | A-2：用 LLM 把训练问法改写成口语，产出 D7；带数字 / 实体 / 结论词守卫 |
| 守卫 | 改写后自动拒绝规则：数字集合不变、实体保留 ≥60%、不新增结论 / 判断词、去重、长度 |
| SEALED / 封存 | test 切分文件的 sha256 记录（`data/planner/sft/SEALED.md`），`check_sealed.py` 校验不被改动 |
| 泄漏（leakage） | train 与 test 出现相同或近似样本；用 bigram-Jaccard 检查为 0 对 |

## 3. 五级系统模式（E-1）

定义于 `src/graph/system_modes.py`，PLAN §0.5。相邻两级只差一组开关。

| 模式 | key | 中文 | 相对上一级新增 | 对应 |
|---|---|---|---|---|
| mode1 | `llm_only` | 纯 LLM | 无工具，LLM 直接回答 | 参照 |
| mode2 | `tool_base` | 工具基座 | 五工具 + two_way 检索 + 图谱 + lexical 反思；expert 归因、无 EIG；Planner baseline / free；Generator text；Validator off | 工程基座 |
| mode3 | `active_plan` | 主动规划 | calibrated 归因 + with_eig + planner_strategy active | 主线一 |
| mode4 | `claim_verify` | 声明验证 | generator_output claims + validator_mode route | 主线二 |
| mode5 | `dpo_planner` | DPO 规划器 | planner_mode finetuned | 主线三 |

相关开关：

| 开关 | 取值 | 含义 |
|---|---|---|
| `planner_mode` | `baseline` / `finetuned` / `oracle` | Planner 用通用 LLM / 微调模型 / 金标（见 Oracle） |
| `rag_mode` | `naive` / `two_way` / `None`（不启用）| 单路 BM25 / 子块 + 锚点两路 RRF |
| `reflection` | `off` / `lexical` / `llm` | 反思关闭 / 词法打分 / LLM 打分 |
| `attribution_mode` | `expert` / `calibrated` | 归因引擎参数 |
| `with_eig` | 布尔 | 归因输出是否附 EIG 推荐；对应环境变量 `FAULT_ATTR_EIG` |
| `planner_strategy` | `free` / `active` | 见 §2.4 |
| `generator_output` | `text` / `claims` | 生成纯文本或结构化声明 |
| `validator_mode` | `off` / `check` / `route` | 关闭（v1 整体评分）/ 只做声明核查不路由 / 核查 + 三路路由；对应 `ValidatorAgent.claim_check` |
| Oracle / OraclePlanner | 用 D10 金标 `required_actions` 直接生成计划的理想 Planner | 给出系统上界（97.4%），不是真实模型 |
| `--tag` / smoke | 评测脚本旁路运行标记；`smoke` 为冒烟测试（少量样本、不进正式报告） |
| `--no-llm` | 关闭 LLM 走确定性回退，用于回归 |

## 8. 评测指标缩写

| 缩写 | 全称 / 计算 | 用于 |
|---|---|---|
| Top-1 / Top-3 | 最高概率故障命中真实标签 / 前三命中 | 归因引擎 |
| R@k / Recall@k | 前 k 个检索结果含金标块的比例 | 检索（k=1/3/5/10） |
| MRR | Mean Reciprocal Rank，金标排名倒数均值 | 检索 |
| RRF | Reciprocal Rank Fusion，两路检索结果按名次倒数融合 | `two_way` 检索 |
| BM25 | 经典词频检索算法 | `rag_search` |
| Kappa | Cohen's Kappa，两位标注者一致性系数 | D9 人工评分、图谱抽检 |
| 任务成功率 | 端到端：动作正确 + 参数正确 + 结果有效 + 忠实度达标同时满足 | D10 |
| 动作正确率（action acc） | Planner 调用的工具序列与 `required_actions` 一致 | D10 / Planner 离线 |
| 参数正确率（param acc） | 工具参数关键字段与金标一致 | 同上 |
| 完整调用率 | 金标要求的所有调用都发出 | Planner 离线 |
| 不必要调用率 | 金标不要求却调用了 | Planner 离线 |
| 追问正确率（ask acc） | 应追问场景确实追问 | Planner 离线 / D10 ask_user |
| 错误恢复成功率 | 工具报错后改参数重试成功 | Planner 离线 error_recovery |
| 格式合法率 | Planner 输出可解析为合法 JSON 动作 | Planner 离线 |
| 忠实度 / faith | 结论中引用的数字与证据锚点与工具结果一致的代理分（0–1） | D10 |
| tool_result_valid | 工具返回非空且结构合法 | D10 |
| 平均 inquiry_rounds / evidence_rounds | 每样本追问轮数 / 补证轮数 | 五级评测新增 |
| 平均调用次数 / LLM 调用 / Token | 成本指标 | 各评测 |
| p 值 / p<0.0001 | 统计显著性（B-5 用配对检验） | 问询次数差异 |
| 上界（Oracle 上界） | Oracle Planner 达到的成功率 97.4%，代表「规划全对」时的系统能力 | 五级评测 |
